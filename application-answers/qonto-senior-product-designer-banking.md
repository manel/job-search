Describe a recent product design project you were particularly challenged by and how you approached the problem.

At Abacum, finance teams configured datasets by editing JSON files. The goal was customer autonomy for most standard setups, with less help from our implementation team. The request was a nicer JSON editor. I doubted that would work and asked for research first.

In testing, participants could write a transformation with Excel functions but couldn't write the same logic in SQL inside the tool, so the barrier was SQL itself. I recommended an ordered list of dataset actions, like transform and aggregate, written in a syntax close to Excel by extending Abacum's own modeling language.

Product and Engineering pushed back. Extending the language was slower to build than the SQL approach engineers already used. They asked for the research evidence and more checks before agreeing, and existing customer datasets meant we couldn't risk changing their data. I brought the test findings back and argued the direction was more useful for users.

Dataset Manager shipped as a guided, self-serve flow. The implementation team's read was that standard configuration took about half the previous time, and customers could reach a working setup in their first session.
