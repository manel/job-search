Hello Otodom team,

The role centres on a contribution model and on resolving conflicts between a tribe's local need and the system's coherence. That was most of my work on Abax at Abacum, where five squads shipped product on a shared system without a dedicated platform team.

I proposed and ran the contribution split there. Work in progress lived in an Exploration file published with an [Experiment] prefix, and components entered the canonical Implementation library only after review in a weekly sync that every designer attended for more than eight months. Disputes came through the same sync. Component naming was argued case by case until I wrote a convention the team adopted, and read-only state ended up as an adapted MUI state instead of a new one. New components shipped behind feature flags and each squad added its own migration tickets, so squads ran their own rollout.

At Remuner I was the only designer and built the system from scratch, with ESLint rules that enforced system components. I owned the design side of the token pipeline and used Codex to add CI validation and drift detection through PRs that engineers reviewed and merged. I also used the Figma MCP with an AI agent to keep tokens in sync with code, check contrast and write component documentation.

Since my application in July, the design-systems case has been updated with these decisions: manel-leiva.com/cases/design-systems.
