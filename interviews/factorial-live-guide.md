## 10:00 — ASK (8 min, before Figma)

Pick 2 to 3 that fork THIS brief. Say the fork out loud.
Then state assumptions and invite correction: "I'll assume X. Stop me if wrong."

- [ ] **WHO** is the primary user? (3 users = 3 products. Make them pick.)
- [ ] **WHICH PROBLEM**, if the term is vague?
- [ ] **OPTIMIZE FOR** speed / compliance / errors / quality?
- [ ] **AUTHORITY / VISIBILITY** — who approves, who sees, central or delegated?
- [ ] **PLATFORM** — desktop / mobile / kiosk?
- [ ] **BOUNDARY** — greenfield or extension? Is X in scope or an input?

Name one hidden branch you're NOT resolving now: "Before I lock this I'd clarify ___."

---

## 10:08 — FRAME (on the Figma page, leave visible)

Answer in one line each. Don't design yet.

1. **Primary user** (pick one, no hedge)
2. **The one job** with most friction/cost
3. **Success / failure** looks like
4. **Business objective** + the metric I'd move (1 line, no metrics section)
5. **Core loop** (daily/weekly, not edge cases)
6. **MVP boundary** — v1 includes ___, explicitly NOT ___
7. **Real problem** vs what the brief named

---

## 10:18 — STRUCTURE (boxes + arrows, no UI)

- [ ] Entry point: how do they arrive?
- [ ] The 3 to 5 decisions/steps
- [ ] States: empty / in-progress / complete / error / edge
- [ ] Output: what they have at the end they didn't have at the start
- [ ] Pick your ONE spine decision: "I chose X over Y because Z"

**Cut scope with the 7 axes** (defer = name it out loud):
config/admin · upstream · downstream · permissions · rules engine · adjacent inputs · platform variants
→ Assume away hard inputs (balance is a number, not an engine).
→ Risk is OVER-building. Cut more than feels comfortable.

## 10:30 — DESIGN (1 to 2 screens)

- [ ] The screen where the core problem is SOLVED (not settings, not onboarding)
- [ ] Annotate on the screen: "happy path only", "X deferred", "Y is input"
- [ ] Make the spine decision visible

Still in flow diagrams? STOP. Open a screen now.
