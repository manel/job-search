# Assess fit

Read `context/positioning.md`, `context/applications.md`, and `memory.md` first.

Then evaluate the role provided in $ARGUMENTS against this framework:

- Domain (B2B SaaS / fintech / data-heavy / complex workflow): pass / marginal / fail
- Scope (Senior, Lead, or Staff IC only — no management): pass / marginal / fail
- Work type (product design and systems thinking, not UI production): pass / marginal / fail
- Location (remote or Barcelona hybrid only): pass / fail
- Genuine interest (would Manel actually want this job): pass / marginal / fail
- Stack signal (Figma, design systems, complex workflows in JD): pass / marginal / fail

For design-systems-titled roles, add one check:
- DS maturity (does the org treat the system as product infrastructure — dedicated scope, a named system, engineering investment — or as a side project / support function / pre-sales asset?): pass / marginal / fail. Merkle and Fluidra are the reference failures: DS in the title, no shipped-product DS work behind it.

Give one decision: Proceed / Defer / Skip. Follow with two or three sentences of honest rationale. Do not dress up a skip as a defer. A weak score on Domain or Genuine interest is a skip, not a defer.

Also flag: is there a plausible warm path into this company, based on `context/applications.md` and `context/outreach.md`?

Record the outcome in `context/applications.md` (Deferred or Assessed and skipped table, or note that an application is proceeding).

Do not write any CV or cover letter copy. Assessment only.
