# Assess a role

## Inputs

Job description or reliable posting URL, company, role, and any known contact or prior application.

## Checks

1. Read the positioning, target-role constraints, and existing application records.
2. Assess domain, IC scope, work type, location, genuine interest, and relevant stack signals.
3. For a design-system role, assess whether it is real product infrastructure with engineering investment and ownership.
4. Verify the actual level from responsibilities and experience requirements; do not rely on the title.
5. Reject explicit people-management scope unless Manel changes the IC-only constraint.
6. Identify the one portfolio case that proves the role's rarest requirement and verify that it is live.
7. Check for a warm path. Use it before or alongside the application; do not delay a ready application indefinitely.
8. Check prior applications to the same company. Repeated screen-level rejections require materially changed evidence, a different role shape, or a credible warm path before reapplying.

## Output

Give one decision: Proceed, Defer, or Skip. State the evidence, main risk, level read, proof case, and sourcing path. Record the decision before drafting any CV, letter, or outreach.
